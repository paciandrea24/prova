**Tech Stack:** Node.js, `node --test` + `node:assert/strict`, moduli UMD condivisi (`frontend/shared/*.js`), Three.js r128 lato client.

### Task 1: Sul fianco alto il muro sta subito dopo il cordolo

### Task 3: Niente oggetti sul fianco del cuneo

Gli asset scenici hanno il pivot alla base e stanno dritti: sanno posarsi solo su una superficie orizzontale, e su una parete escono storti o mezzi sepolti. Il fianco del cuneo — la rampa con cui il terrapieno scende dalla quota del bordo alto al prato — e' esattamente quella parete. La quota giusta gli asset ce l'hanno gia' (`terrainHeightAt` conosce il cuneo dalla fase 1b-1); manca il **dove**.

⚠️ Non si applica la regola dei ponti: **un ponte e' sospeso nel vuoto, una sopraelevazione poggia sulla terra**. Oltre il cuneo, dove il terreno torna piano, gli asset ci vanno eccome — altrimenti la curva banked diventa un buco spoglio in mezzo alla scenografia, che e' il difetto che si nota di piu' (decisione dell'utente, spec fase 1b).

    // gli oggetti ci vanno — una sopraelevazione poggia sulla terra, non e' un
    // ponte — ma sulla rampa con cui il terrapieno scende dal bordo alto al
    // prato no: gli asset hanno il pivot alla base e stanno dritti, quindi su
    // una parete escono storti o mezzi sepolti.
    //
    // La pendenza si misura come la vede la mesh — due sonde a un passo di
    // distanza — invece di ricavarla dal rollio: cosi' vale anche per le
    // discese normali, che hanno lo stesso problema da sempre.
    const PENDENZA_TERRENO_MAX = 0.25;    // 14 gradi
    const PASSO_SONDA = 2;
    function terrenoTroppoInclinato(x, z) {
        const q = (dx, dz) => TrackGeometry.terrainHeightAt(
            groundPts, x + dx, z + dz, embankStart, embankOuter);
        const dyX = (q(PASSO_SONDA, 0) - q(-PASSO_SONDA, 0)) / (2 * PASSO_SONDA);
        const dyZ = (q(0, PASSO_SONDA) - q(0, -PASSO_SONDA)) / (2 * PASSO_SONDA);
        return Math.hypot(dyX, dyZ) > PENDENZA_TERRENO_MAX;
    }
```

            const perUnita = Math.abs(a - b) / passoPista;
            if (perUnita > saltoMax) { saltoMax = perUnita; doveSalto = i; }
        }
        if (saltoMax > TrackSegmenti.PENDENZA_ROLLIO_MAX * 1.5) {
            aggiungi('da guardare', 'sopraelevazione-a-scalino',
                `La sopraelevazione cambia di ${(saltoMax * 180 / Math.PI).toFixed(1)} gradi per unita' di pista:`
                + ` si sentira' come uno scalino sotto le ruote. Di solito il tratto e' troppo corto per la curva che ci si vuole mettere.`,
                { x: pts[doveSalto].x, z: pts[doveSalto].z });
        }
```

⚠️ **`giro` e `pts`**: sono le variabili che `controllaGeometria` ha gia' (la lunghezza del giro e i campioni di `sampleLoop`) — usare quelle, non ricalcolarle. Se `pts` non porta `rollio` (viene da `sampleLoop` sui controlPoints), verificare che il campo sopravviva al campionamento: se non c'e', il primo dei due controlli non scattera' mai e il test lo dira'.

⚠️ **`TrackSegmenti` e' importabile da `trackValidatore`?** Il modulo e' UMD e dichiara le dipendenze in cima al file (`factory(require('./trackGeometry.js'), ...)`): aggiungere `trackSegmenti.js` li' **e** nella riga del ramo browser, o le costanti arrivano `undefined` solo in pagina e i test non se ne accorgono.
